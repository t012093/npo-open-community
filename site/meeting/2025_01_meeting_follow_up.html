    1. 業務効率化のための改善提案¶

    コミュニケーションフロー¶

    graph LR
    A[情報・課題の発見] -->|事前共有| B[メッセージ共有]
    B --> C{反応の種類}
    C -->|同意| D[スタンプ]
    C -->|意見あり| E[リプライ]
    C -->|質問あり| F[質問投稿]
    G[24時間経過] -->|リアクションなし| H[再プッシュ]

    連絡について¶

    基本ルール

    • 必要な情報や課題を発見した際の対応：
      • ミーティング前にメッセージでの事前共有を推奨
      • 関連するプロジェクト業務への対応：
        • 概ね同意の場合：スタンプでのリアクション
        • その他：リプライでの意見提示または質問
      • リアクションがない場合は再度プッシュ
      • 原則24時間以内の返信を目指す

    ミーティングに関して¶

    項目 内容 優先度
    出席 可能な限り時間通りに参加 高
    事前準備 各自共有可能な資料の作成 中
    議事録 作成を徹底 高
    資料確認 共有された資料は必ず目を通す 中
    保育アプリ機能選定 詳細機能の検討と決定 高

    保育アプリ機能選定について¶

    機能選定の方針

    • 基本機能と追加機能の明確な区分
    • ユーザーニーズの優先順位付け
    • 実装の技術的な実現可能性の評価

    機能階層の説明(smple)¶

    階層 説明 具体例
    必須機能 アプリの核となる基本的な機能で、無料プランでも必ず提供される機能 施設検索、お知らせ配信、ブログ観覧
    標準機能 基本機能の一部として提供されるが、必須ではない補助的な機能 健康記録、お便り帳機能、
    プレミアム機能 有料プランで提供される高度な機能 AIによる成長記録分析、保育計画支援
    オプション機能 必要に応じて追加できる独立した機能モジュール 外部サービス連携

    機能選定のポイント

    • 必須機能は保育業務の基本的なニーズを満たすことに注力
    • 標準機能は保育現場の業務効率化を支援
    • プレミアム機能は付加価値の高いサービスを提供
    • オプション機能は施設ごとの個別ニーズに対応

    検討事項¶

    カテゴリ 検討内容 優先度
    基本機能 施設検索 高
    基本機能 お知らせ配信 高
    基本機能 ブログ機能 高
    追加機能 AIchat,出席確認、 中
    追加機能 保育計画支援、写真共有 中
    オプション 外部連携、企業向けAPI 低

    サービスモデル概要¶

    基本方針

    寄付型を想定した無料プラン + 機能追加による有料プラン制

    プラン 特徴 対象ユーザー
    無料プラン 基本機能の提供 一般ユーザー
    有料プラン 追加機能の提供 プロフェッショナルユーザー
    寄付 サポーター特典 支援者

    採用理由：¶

    1. NPO法人化要件との整合性
    2. 無料形態が法人化要件となる可能性
    3. 現行サービストレンドとの適合性
    4. 企業側のメリット
    5. 寄附を通じたPR効果の創出

    トレンド分析¶

    • 生成AIの活用
    • 個人開発者の増加傾向

    法人化の進捗¶

    進行中の課題

    定款関連：理事会のオンライン対応、アンケートによる承認形式について県と協議中。テンプレートで問題なければそのまま採用

    3. アプリケーション開発について¶

    バックエンド開発要件¶

    優先して作成が必要な文書

    バックエンド開発を開始する前に、以下の文書の作成が必要です： 1. 要件定義書：システムの基本要件と機能要件の明確化 2. 詳細設計書：システムアーキテクチャと実装詳細の定義 3. API使用設計書：外部サービスとの連携仕様の定義

    graph TB
    A[バックエンド開発] --> B[必要書類]
    A --> C[データベース]
    B --> D[要件定義書]
    B --> E[詳細設計書]
    B --> F[API使用設計書]
    C --> G[Tokyoリージョン]
    C --> H[データ移行設計]

    データベース選定について¶

    検討事項

    • 現在の候補：Supabase
    • 検討ポイント：
      • スケーラビリティ
      • コスト効率
      • 運用の容易さ
      • データ移行の柔軟性
    • リージョン選定：
      • Tokyo リージョンの利用を検討
      • データの所在地に関する法的要件の確認が必要
